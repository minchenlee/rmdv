# rmdv v0.8.0 — a Settings page, window glass, and Quick Slots

> Prepared 2026-10-07, updated 2026-10-09. Not published: the tag, release,
> and site deployment each wait for owner authority.
>
> Source: `main@7e1866d` plus this notes update; tag: `v0.8.0`.

rmdv v0.8.0 puts every preference on one page, adds optional macOS window
glass, and lets you keep nine files one keystroke away. It also refreshes the
look of every theme and makes search, the sidebar, and editing faster on large
documents and folders.

## Highlights

### Settings page (`⌘,`)

- One page for every preference, grouped as Appearance, Reading, Agent & CLI,
  and Advanced. Open it with `⌘,`, the gear button in the sidebar header, or
  **Open Settings** in the command palette.
- Theme cards preview each theme; click one to apply and save it.
- Switches for Soft syntax colors, the status footer, hidden files, Mindmap
  auto-center, and focusing the window on agent navigation.
- Font size, window glass mode and opacity, CLI install, the themes folder,
  and the preferences file are all on the same page.
- Fully keyboard-driven: `↑`/`↓` move, `←`/`→` change a value, `Space`/`Enter`
  toggle, `Esc` closes. Every change is saved at once.

### Window glass (macOS)

- Choose **Off**, **Sidebar**, or **Window**. The sidebar or the whole window
  shows a blur of what is behind it.
- On by default: new installs open with whole-window glass at 60% opacity.
  A saved choice, including **Off**, is kept.
- Glass opacity is adjustable from 60% to 90%.
- Turning glass on from **Off** needs a restart; the Settings page offers a
  **Restart rmdv** button that reopens the current file.

### Quick Slots

- Nine slots per workspace folder. `⌘N` adds the current file to the next
  empty slot; `⌘1`–`⌘9` jump to a slot; outside Zen, `⌘↑`/`⌘↓` cycle slots.
- A slot remembers whether the file was open as a rendered document or a
  Document Mindmap.

### A refreshed look

- One set of derived colors and a 4/6/10/16 corner-radius ladder across the
  app. Dialogs, cards, toasts, and tooltips sit one elevation step above the
  content.
- Light themes have clearer contrast. Every built-in theme passes the text
  contrast floors (body text ≥ 4.5:1).
- Code blocks have a quieter fill, a hairline border, and more padding.
- **Soft syntax colors**: an optional, desaturated syntax palette.

### Faster on large documents and folders

- In-document search on an 8 MiB document: 84–123 ms → 17–33 ms per search,
  with about 495,000 → 40 allocations. Typing in the find bar no longer stalls.
- Sidebar with 4,000 rows: 4.98 ms → 0.16 ms to build.
- Fewer whole-document passes per editor keystroke; local images load off the
  UI thread; window move and resize bursts are coalesced; the Mindmap syncs
  its animation state only when nodes change.
- Vault search memory is bounded per file, and the file finder reuses its
  results until the query or file list changes.

## Fixes

- Markdown tables follow the reading-pane width: columns grow to fill a wide
  pane, wrap in a narrow one, and scroll sideways only when they cannot fit.
- The reading area in the Mindmap leaf panel and in Full Mindmap uses the
  full panel width.
- Bold text uses Inter Bold. It no longer falls back to a monospace face;
  medium and semibold labels are fixed the same way.
- Currency amounts such as `$3.3 billion … $1.06` are no longer read as
  inline math, so bold and other formatting around them render normally.
- Keyboard shortcuts work under non-Latin input sources such as Zhuyin and
  Pinyin.
- The command palette is centered vertically.
- Mind map labels now scale with zoom, one pixel at a time, instead of
  staying at 14 px and spilling past their nodes when zoomed out.
- `⌘Z` undo works again, and a document with unsaved edits can be reopened.
- The chosen theme is kept across launches.
- Folders that the workspace scan budget skipped now show their files when
  you expand them.
- Opening a folder from the CLI no longer shows a "Couldn't open file" card.
- Inside tmux and other multiplexers that change `TMPDIR`, the `rmdv` CLI
  reaches the running window instead of starting a second instance.
  `RMDV_SOCKET` selects an explicit socket for isolated instances.

## Under the hood

- CI runs the test suite on Linux and macOS and checks the Windows build on
  every pull request; release builds start only after the tests pass.
- The release workflow fails closed: DMG containers are signed, notarized,
  and stapled, and every artifact is checked before publication (`MDV-021`).
  A re-run release no longer loses the PDF engine to a warm build cache.
- Configuration files are written atomically; IPC requests and file sizes
  are bounded.

## Known limitations

- After `rmdv goto`, a table row clipped at the top of the viewport can render
  without text (`MDV-038`).
- Windows builds remain best-effort and have no PDF extraction.
